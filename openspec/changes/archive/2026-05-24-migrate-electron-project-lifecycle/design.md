## Context

The native app's first real workflow is opening or creating a wiki. The Electron shell already has main/preload/renderer boundaries, but it only displays shared resource metadata. This phase migrates the "open existing project and inspect files" foundation.

## Goals / Non-Goals

**Goals:**

- Match native file filtering and ordering in a reusable core helper.
- Keep renderer sandboxed and route filesystem access through IPC.
- Provide a visible Electron flow for opening a project and selecting files.
- Commit the npm lockfile generated by installing Electron dependencies.

**Non-Goals:**

- No scaffold/new wiki implementation.
- No CodeMirror or compiled preview.
- No background compiler or file watcher.

## Decisions

- Put filesystem scan/read helpers in `@wikiwise/core` so future Electron features and tests do not duplicate native rules.
- Return serializable plain objects from IPC: project root path, tree nodes, selected file, and content.
- Keep the renderer framework-free for this phase to avoid bundler setup before behavior parity demands it.
- Mark deferred actions in the UI instead of hiding them, so visual structure stays close to the native welcome flow.

## Risks / Trade-offs

- The renderer will initially display plain text content instead of CodeMirror; editor parity is a later phase.
- Directory expansion is one level in this phase; recursive lazy expansion will be added with richer file tree parity if needed.
- macOS open dialog behavior is implemented first; Windows/Linux picker parity will need manual checks later.

## State Model

- **welcome:** no project is open; welcome actions are visible.
- **opening:** native dialog is active or project is loading.
- **project-open:** root path and tree are loaded.
- **file-selected:** selected file content is loaded in the detail area.
- **error:** last lifecycle operation failed and the error is visible.

## Migration Plan

1. Write failing core file tree tests.
2. Implement `scanOneLevel` and `readTextFile` in `@wikiwise/core`.
3. Write Electron structural tests for IPC/preload/renderer project lifecycle additions.
4. Implement IPC handlers, preload APIs, renderer state, and CSS.
5. Verify tests and OpenSpec.

## Open Questions

- New wiki creation moves to a dedicated scaffold phase.
- Recursive tree expansion may be handled in the file tree parity phase or alongside editor/preview depending on UX needs.
